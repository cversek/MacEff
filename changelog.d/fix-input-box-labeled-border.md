### Fixed

- **The input box is found again when its border carries the session's name** (`pd/wake.py`): client 2.1.300 prints the session's name in the box's top border, and the screen reader required a border of rule characters only. Every screen read as a dialog, so the daemon typed no mail wake into such a session, and the compact follower typed its prompt but never pressed Enter. A border may now carry one label, and still needs at least 20 rule characters. A captured screen is added to the fixtures.
- **The compact follower types only into an idle, empty input box** (`compact_followup.py`, policy `autonomous_operation` §5.4, `capability_boundaries`): text typed after a draft is sent with it as one prompt. A follower's unsent prompt sat in a box for 29 hours, and the next `inject compact` typed `/compact` onto its end, so it went as plain text and no compaction ran. The follower now waits for the box to empty, and says so if it never does.
- **`inject` refuses to type a command after text already in the box** (`supervisor.py`), reading the box even while a turn runs (`pd.wake.draft_text`), and says what is there. When the screen can't be read it types as before.
