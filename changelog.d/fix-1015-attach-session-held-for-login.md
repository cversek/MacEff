### Fixed

- **Attach reaches a session that can't log in** (`utils/attach.py`, `pd/core.py`, `pd/interface.py`, `pd/cli.py`, policy `persistent_layer` 3.2): MIS-0002-R19 holds such a session failed but keeps it running, so a person can run `/login` in it, and the policy's alert says to attach and do that. Attach refused every failed unit, so the one way back was closed: `nothing attachable hosts its session (the session unit is failed; no session runs)`. A unit's status now carries what the client said (`auth_failed`), attach treats a session held for its login as live and says to run `/login`, and `pd status` prints the cause beside the failed state. `UnitStatus` now ignores fields it doesn't know, like the reply it belongs to, so an older CLI can still read a newer daemon's status (#816). Fixes #1015's case.
