### Fixed

- **`pd install --force` on macOS replaces a loaded job** (`platform/launchd.py`, `pd/adapter.py`, policy `persistent_layer` 6.5). It wrote the new plist and then bootstrapped a label launchd already had loaded, which launchd refuses. A `kickstart -k` after it would have restarted the job from the definition read at its first bootstrap, not from the new plist. A forced install now boots the job out, then bootstraps the new plist. The bootstrap starts the new daemon, which adopts the running units, so `agent init --update` doesn't restart it a second time on launchd.
- **`agent init --update` doesn't move a pinned daemon** (`agent_stack.py`, policy `persistent_layer` 6.5). The unit it renders runs whichever interpreter runs `agent init`. On a login with several macf installs, that could quietly move a daemon off the venv it was given. When the installed unit's program differs from the one it would render, the daemon step names both, under `--plan` too. `--update` then refuses that step unless `--repoint` is given.
