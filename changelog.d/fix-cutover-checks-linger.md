### Fixed

- **The cut-over plan checks that linger is on, and doesn't say Ready when it is off** (`pd/cutover.py` `_linger_check`, `harness cutover --accept-no-linger`, #860 item 11): `harness cutover` reported "Ready: every check holds" while `loginctl` Linger was `no` for the user, so the move left a daemon and a session that stop at the last logout and don't start at boot, which defeats an always-on agent; `pd install` mentioned it only as a note. On systemd the plan now has a `linger` check: on holds; off fails, naming `loginctl enable-linger` as the host operator's call and `--accept-no-linger` as the way to move anyway (the flag is carried into the transient unit `--run` starts, so the plan it rebuilds agrees); one that can't be read is said, not failed. launchd hosts have no such check.
