### Fixed

- **On macOS the primal daemon is listed as `maceff_pd`** (`platform/launchd.py`, policy `persistent_layer`, MIS-0002-R06): the LaunchAgent gives launchd the interpreter as `Program` and `maceff_pd` as `argv[0]`, so `ps` and `pgrep maceff_pd` find the daemon by its identifier rather than as the interpreter. macOS can't rename a running process, so the name is given at exec. A framework-build interpreter (Homebrew's, python.org's) is started through its Python.app directly, with `__PYVENV_LAUNCHER__` naming the venv as the build's launcher would, so its re-exec can't rename it. One limit remains: the kernel's own name, which `top` shows, stays the interpreter's. An installed agent gets the new plist when it is installed again.
