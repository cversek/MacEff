### Changed

- **The inbound receiver and its tunnel are supervised units, alive only when working** (`amail/daemons/receiver.py`, new `amail/daemons/tunnel.py`, `start.py`, persistent_layer 8). The amail step no longer launches either: each is a declared unit of its account's primal daemon. The receiver reads its parameters from its env file and beats only when its own `/healthz` answers over loopback. The tunnel wrapper runs `cloudflared` with metrics on loopback, beats only while `/ready` reports an edge connection, says "connected" only then, and exits when `cloudflared` does, so its daemon restarts it. Start-up names the unit running each, refuses a placed `receiver.env` that no unit runs, and warns on a tunnel config with no tunnel unit. **A deployment must declare both units before taking this version.**
