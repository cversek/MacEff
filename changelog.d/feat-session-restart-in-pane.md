### Changed

- **Restarting the session unit restarts the session in its pane and keeps its tmux server, so an attached terminal survives** (`pd/session_unit.py`, `pd/core.py`, #726): a restart ended the unit's whole process group, the agent's own tmux server with it, and an operator attached through iTerm2's control mode had the window crash. On SIGUSR1 the wrapper now keeps the pane (`remain-on-exit`), reaps the old session's process groups as the unit's own end reaps them, SIGTERM and then SIGKILL, so two sessions never resume one conversation, and runs the pane again. Each pane it starts is announced as a `pd_session_pane` event. The daemon sends SIGUSR1 only to a wrapper that announced itself, to the wrapper's pid alone, and counts the respawn as the session's new incarnation, with the report a restart owes (MIS-0002-R47). A wrapper from before this change, one that ends instead, or one that doesn't report the respawn within the unit's stop grace is restarted whole, as before, and the unit's state event says which happened.
