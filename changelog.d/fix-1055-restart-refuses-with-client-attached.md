### Fixed

- **A restart of the session unit that would end its tmux server refuses while a client is attached** (`pd/core.py`, `pd/session_unit.py`, `pd/cli.py`, #1055): a restart the wrapper can't carry out in the pane (a wrapper from before the pane restart, a respawn it didn't report in time, a declaration that changed) ends the tmux server, and with it every attached terminal, so an operator's iTerm2 window in control mode crashed with no word. The daemon now counts the clients attached to the unit's server first and, when there are any, refuses with how many and what to ask: `macf_tools pd unit restart session --server --reason ...` restarts the server anyway. A restart in the pane is never refused, since it keeps the clients, and neither is a restart with no client attached. When `claude` ends on its own the unit still exits and restarts with a new server, as before. Also: a wrong `noqa` code on the wrapper's wait loop, which the silent-handler check had been reading as no waiver.
