### Fixed

- **`harness attach --control` says it needs iTerm2 instead of hanging on any other terminal** (`utils/attach_dispatch.py`, `cli.py`, #987): tmux control mode (`-CC`) speaks a protocol only iTerm2 understands, so on any other terminal the command printed nothing and never returned. It now checks the terminal before it execs: `TERM_PROGRAM=iTerm.app`, or `LC_TERMINAL=iTerm2`, which survives ssh and tmux. Elsewhere, an explicit `--control` is refused with exit status 2, and the message names `--no-control` (which also overrides a declared `control: true`) and `--read-only`; a declared `control: true` that this terminal can't use falls back to a plain attach with a line on stderr. `persistent_layer` 9.5 says so. The check is on the command that would run, so a `control` default from a remotes declaration and an ssh hand-off that carries `-CC` are covered too. `MACF_ATTACH_CONTROL=force` lets a terminal the check doesn't recognize try it.
