### Fixed

- **A unit still failed for its login is recorded failed again each day** (`pd/core.py`, policy `persistent_layer` 5.1): the `failed` state is written once, and a session that beats steadily writes no other state event, so the record could be rotated into an archive by `macf_tools events rotate`, or outlive the outside watch's seven-day lookback, while the process kept beating. The watch then read fresh liveness with no failure, and reported the session healthy, and could send a "recovered" that wasn't true. The core now repeats the failed state once a day, as the same state of the same process, with the reason saying it is still failed and when it was first recorded, and a `since` on the record so `pd status` still says when the failure began, not when it was repeated. The session is not restarted, and every reader that takes the newest state reads the same thing (#896).
