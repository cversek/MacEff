### Fixed

- **A schedule may target only an isolated session or its own agent's live session** (`pd.interface.Declaration`, MIS-0002-R29, policy `persistent_layer` §10.4): `target` accepted any non-empty string and was never compared with the declaration's agent, so a schedule naming another agent's card loaded and was silently never run. Such a declaration is now refused at load, naming the target and the two values allowed.
- **The primal daemon holds an owed notice whatever its age** (`pd.notifier`, MIS-0002-R41, policy `persistent_layer` §1.8): a restarted daemon read the event log back only one day, so a notice still owed after a longer downtime was dropped. Each start now appends a `pd_notices_owed` checkpoint of what it still owes, and the next start reads back to the newest one instead; a log with no checkpoint yet reads back one day once. Only the newest daemon-raised notice per thing is owed (per schedule for run failures, per entry for an entry's wake), so a crash loop while the session is down comes back as one notice, not hundreds.
