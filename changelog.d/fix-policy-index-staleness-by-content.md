### Fixed

- **The policy index's staleness check compares content, not times** (`utils/manifest.py`, `cli.py`, #898). A checkout re-stamps files whose content didn't change, so after a pull `policy recommend` said policies had changed when none had, and a policy restored with an old time was missed. `policy build_index` now appends a `policy_index_built` event naming the index and each policy's sha256, and the check reports a changed, new or removed policy by content. It reads only an event at least as new as the index on disk, so an index rebuilt without one, or built from a directory named with `--policies-dir`, is still judged by time. The warning now also says to restart the search service, which keeps the index it loaded. The index's path is spelled once, in `get_policy_db_path`.
