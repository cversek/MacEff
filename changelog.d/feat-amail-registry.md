### Added

- **The operator's registry of agents' keys and issued certificates** (`macf/amail/registry.py`, `amail registry check`, amail policy §3.2.3, MIS-0004 R42): each MacEff agent's public key is declared with its account in one root-owned file, `/etc/maceff/registry.yaml` by default, which also records each certificate the operator's authority issues by name, serial and expiry, never its key. A key an agent declared in its own contact list proved nothing to anyone else, since anything running as the agent could declare one. The registry is refused when read if anyone but root could write it or the directory that holds it, and a malformed entry is refused by name. A key may carry a timezone-aware validity window, and a key with an end date is retired and never signs (R45); an account declared by two cards is a shared login, and every card on it is returned (R46). It only declares: refusing unsigned agent mail (R43) and marking a failed signature suspect (R44) read it later.

- **The registry is written by `agent init` and by explicit commands, never by hand** (`macf/amail/registry_edit.py`, `amail registry declare|rotate|retire|cert-record|cert-retire`, amail policy §3.2.3), as the repo owner asked on review. Each change is shown as a diff first, is a no-op when already made, and is written by root, or staged with its sha256 and the one root step that installs exactly those bytes, checking root's own copy against that sha256 before it is renamed into place. `--dry-run` writes nothing. `agent init` declares the agent's own signing key the same way. A rotation declares the new key and retires the old one at the same moment, in R45's order; a second key is never declared beside one that may still sign, and a rotation that would leave a time with no key is refused. A certificate can be retired before its expiry.
