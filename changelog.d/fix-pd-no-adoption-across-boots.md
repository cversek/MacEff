### Fixed

- **A restarted daemon never adopts a unit from a record of another boot** (`pd/core.py`, `pd/interface.py`, policy `persistent_layer` §11.1): adoption matched a pid and its start time, and on Linux a start time counts clock ticks since boot, so after a reboot a new process could carry the pid and ticks an old record names, and be taken for the unit. Each unit state event now records the kernel's boot id, and only a record of the current boot is adopted. Boots are compared by id rather than boot time, which moves when the clock is stepped. A record without the id, from before this change or from macOS, is judged by pid and start time as before. Four tests; the check planted out fails one.
