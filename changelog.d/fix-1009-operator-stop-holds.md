### Fixed

- **A unit the operator stopped stays stopped across a daemon restart** (`pd/core.py`, policy `persistent_layer`): booting started every declared unit that wasn't `optional`, so a unit the operator had stopped came back with the next restart or declaration change, with nothing saying it had. A model server holding most of a GPU did that twice in two days. The daemon now reads its own `pd_control` events, newest first: when a unit's last start, stop or restart on record is a stop the operator asked for, boot leaves it down. It reads `stopped`, its state event says `held down by the operator since <time>; start it to clear`, and the `pd_carried` report names it under `held`. Only an explicit start or restart clears the hold; a stop the agent or the wind-down asked for isn't held (#1009).
