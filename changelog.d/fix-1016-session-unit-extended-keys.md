### Fixed

- **The session unit's tmux server has extended keys on, whatever its baseline file says, so Shift-Tab keeps working** (`pd/session_unit.py`, `utils/harness.py`, #1016): #986 added `extended-keys` to the rendered baseline, but the session unit starts its server from `~/.tmux-<agent>.conf` as it was written, so an agent whose file predates that change (or has none) still ran with tmux's default (off) and lost Shift-Tab after the first presses. The wrapper now sets `extended-keys always` and the `extkeys` terminal feature on its own server at start, and the rendered baseline says `always` too, the setting the issue's reporter confirmed. A tmux older than 3.2 refuses the option and the wrapper says so. A baseline regenerated with `macf_tools harness generate` is no longer needed for this.
