### Fixed

- **The voice service transcribes the audio a request carries, never a file it names** (`voice/service.py` `_transcribe_staged`, `macf_tools voice transcribe`, #868): the service's port answers any local process, and a `transcribe` request that named a path made it read any file its account can, for a caller who may not, so it was a confused deputy for audio. The caller now reads its own file and sends the bytes (`audio`, base64, with the `suffix` that gives its format, one of `.oga .ogg .opus .wav .mp3 .m4a .flac .webm`, at most 64 MB); the service stages them in a private (0700) directory it removes afterwards, and a request that names a path is refused whether or not the file exists, without opening it. `macf_tools voice transcribe` sends the bytes when it routes to the running service. A request line is read only up to about 87 MB, the base64 of the largest audio and room for its JSON, and refused unread beyond it, so no caller can make the service hold more by sending without end; the command doesn't send a file over 64 MB to the service. The proxy's credential forwarding and the search service's answering any local caller, the other parts of #868, are not changed here.
