### Added

- **`macf_tools amail peer add <card>`: declare a rung-2 peer from its card** (`peer_setup.plan_add`, amail policy 2.1.2): writes the peer link with its agents map into `peer_links` and a contact for each local agent named (`--for`), editing the operator's broker config and addressing file one entry at a time so their comments and other lines are kept. Every edit is refused unless, parsed, it is the old data with exactly that entry changed, and the candidate files must load through the broker's own loader before the change is shown, so a card for this broker's own domain, a domain already shared or a public address is refused before anything is written. Shown first, written on a yes (or `--yes`), each old file kept beside the new one; a no-op when the peer is already declared as the card says; a link's note survives a new card. Prints the registry declarations for the operator and runs none.
