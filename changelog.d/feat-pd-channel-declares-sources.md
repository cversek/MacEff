### Added

- **The MacEff channel says which notice sources it takes, and the primal daemon holds the rest** (`channels/maceff_channel.py`, `pd/daemon.py`, `pd/notifier.py`, `pd/interface.py`, policy `persistent_layer` §1.3, §1.8, §1.9, MIS-0002-R149): right after it connects and checks its peer, the channel writes one line, `{"hello": {"takes": [...]}}`, listing the sources its record accepts, read from the record itself. The daemon reads it without blocking its loop, records `pd_channel_declared`, and writes each notice only to a channel that declared its source. A notice no attached channel declared stays owed, never logged delivered, until one that declares it attaches, so a channel running older code than the daemon no longer drops a record the daemon thinks it delivered. A channel that sends no hello within two seconds declares nothing and is sent nothing; a malformed or unfinished hello, or any write after it, drops the channel. The keystroke fallback counts "no channel" per source, so mail an attached channel didn't declare is still typed, never held forever. Five tests (ten cases) through real sockets; ten planted defects each turn one red.
