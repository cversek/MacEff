### Fixed

- **An agent id that doesn't resolve falls back to the home's calling card, and when nothing resolves it is said once** (`config.py` `ConsciousnessConfig.agent_id` and `unresolved_agent_id`, `hooks/hook_logging.py`, #1036): with no `MACEFF_USER` or `USER` and no moniker in a project config, the id was `unknown_agent` without a word, and the per-session folders and logs were written under that name, hiding whose they were and letting a lookup by agent id miss. The id now falls back to the calling card of the agent's home, the identity the primal daemon uses, before anything else; where no card resolves either, `unknown_agent` is still used (callers need a name) but one line on stderr, once per process, says why, names the process and says whether `MACEFF_USER` and `USER` were set, which is the step the issue asked for to find the process that lacks them. An id that already resolved by the container variable or the moniker is unchanged.
