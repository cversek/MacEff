### Fixed

- **knowledge eval labels learnings named the way the learnings CLI names them** (`knowledge_eval.py`, #1165): the filename pattern matched only names ending in `_learning.md`. So a corpus of `<date>_<time>_<slug>.md` learnings had no cross-reference or same-subject labels at all, and a mixed corpus silently lost part of its labels. It now matches any dated `.md` name. Both callers keep only names that resolve to a learning, and a name counts as unresolved only when it names no node at all. Same-subject clusters are now the ones the learnings CLI reads (`learnings_index.parse_index`): a structural heading such as a CEP navigation guide is not a cluster, a "(N)" count is optional, and an entry line names its own file. Two tests; three planted defects each turn one red.
