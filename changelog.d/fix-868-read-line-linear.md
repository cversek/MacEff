### Fixed

- **The voice service reads a request line in linear time, and the client bounds the reply it reads** (`voice/service.py` `read_request_line`, `send_request`, #868): the bounded read added with the audio-bytes protocol still joined bytes on every 4 KB chunk, which copies the buffer each time, so a caller sending up to the bound slowly kept the service busy: 80 MB took 109 s to read, against 0.03 s appended in place. The client read the service's reply with the same unbounded loop, so a process squatting the port could make it hold an endless reply; it now uses the same bounded reader. A reply that breaks the protocol (too long, not JSON, not UTF-8) is a connection error, so `macf_tools voice transcribe` falls back to direct transcription and the status call reports the service as not responding, rather than either raising.
